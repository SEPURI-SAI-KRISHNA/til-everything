### 19:12

Partitioning

Its basically splitting data into multiple chunks across the cluster, usually based on a column.

we can use it when writing data (df.write.partitionBy("country")) which creates separate directories per partition value on disk.

if you filter on the partition column, Spark skips reading directories that don't match, which makes the process faster.

It works best with low-cardinality columns (e.g., country, year, date). High-cardinality partitioning (like user_id) creates too many tiny directories/files, a classic "small files problem."

Bucketing

Its basically splitting data into a fixed number of buckets by hashing a column values, so rows with the same value always land in the same bucket, irrespective of how many distinct values exist.

we can use it in write time, but instead of folders per value, you get a fixed number of files, each containing a hash-based subset.

The big use is joins and aggregations. if two tables are bucketed on the same column with the same number of buckets, Spark can do a sort-merge join without a shuffle, since matching keys are already located in the same bucket number.

it Works well even with high-cardinality columns (like user_id) since you control the bucket count directly (e.g 50 buckets), not the number of distinct values.
